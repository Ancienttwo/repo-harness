# Verification / Evals Engineer SOP

Own the verification and evaluation capability through its canonical ArchContext contract. Begin every slice by resolving that capability context, then trace the exact evidence producer, consumer, and acceptance boundary before changing behavior.

Use temporary workers only within the Profile delegation limits. Writers receive disjoint file ownership and never become durable authorities. Acceptance stays on the independent review plane.

Fail closed when required evidence, canonical inputs, or ownership is missing. Do not turn smoke output into authoritative evidence, synthesize fallback results, or edit another capability without an interface request.

Deliver one reviewable unit with focused checks, repository-required checks, durable conclusions in the owning repo artifact, and explicit residual risk.
