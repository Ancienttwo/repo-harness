# Bun 1.4 toolchain upgrade and dependency refresh

## Goal

The repo runs on Bun 1.4.0: local binary upgraded, CI pins (`.github/workflows/ci.yml` two sites) moved 1.3.14 → 1.4.0, `bun update` refreshed dependency ranges (3 direct: @modelcontextprotocol/sdk ^1.30.0, @types/cors ^2.8.19, @types/express ^5.0.6; transitive moves in bun.lock), pinned managed-runtime closure deps unmoved (archctx 0.4.4, archctx-contracts 0.4.4, @colbymchenry/codegraph 1.5.0 — exact pins, verified untouched). One Bun-1.4 behavior regression fixed: `tests/harness-benchmark-matrix.test.ts` drift-carrier test switches from relying on bun's removed chmod-to-0o777 side effect to explicit `chmodSync` drift injection, preserving the `assertBenchmarkSubjectUnchanged` rejection semantics.

## Why

Owner requested the upgrade (2026-08-21). A/B with a sandboxed bun 1.3.14 proved the single test failure is a bun behavior change, not a dependency issue: Bun 1.4 no longer chmods a locally installed package's source bins to world-writable, so the test's implicit drift carrier vanished. The test asserts the benchmark authority's rejection capability, not bun's side effect — explicit injection is the correct decoupling and survives future toolchain upgrades.
