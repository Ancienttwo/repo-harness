## Approach
### Strategy
Fix each issue at its root and keep every consumer on one rule. For #453, all five `allowed_paths`
readers drop YAML inline comments the same way, so verify-sprint, the mutation guard, contract-run
and the evidence producers cannot disagree about scope. For #457, adopt fleet agent files into the
ownership manifest only right after the fleet helper has verified them, and never adopt a
receipt-accepted user-managed agent.

### Trade-offs
| Option | Pros | Cons | Decision |
|--------|------|------|----------|
| #453: fix only `verify-sprint.sh` | Smallest diff | Mutation guard, contract-run and evidence producers keep the bug and disagree with verify-sprint | Rejected |
| #453: reject inline comments with an error | Fails closed | Breaks contracts that are valid YAML | Rejected |
| #453: strip unquoted inline comments in all readers | Matches YAML semantics; one rule everywhere | Touches five readers | Use |
| #457: helper recognizes previous package output | No manifest change | Needs every past generator's output; a second ownership authority | Rejected |
| #457: `--force` on update | Trivial | Overwrites accepted user-managed agents | Rejected |
| #457: adopt verified non-user-managed fleet files into the manifest after a successful fleet step | Uses the existing ownership authority; user-managed agents excluded by receipt hash | Needs the receipt read in TS | Use, with the helper moved onto the same TS reader |

### Data Flow
`runGlobalRuntimeSetup` runs the fleet helper as the `install agent fleet` step. Both callers that
then record ownership (`runTransactionalProfileProjection` for bootstrap and
`runCandidateRuntimeReconciliation` for update) pass `agentFleetVerified(result)` to
`applyInstallProfile`. When true and the profile includes `agent-fleet`, each fleet target that is a
regular file and not byte-matched by the user-managed receipt is captured as a
`transaction-created-file` managed surface. The next fleet run's `compareAndWrite` sees a current
`managed-file` entry and overwrites it with the new projection.

## Risk Assessment
| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| A user-edited, unaccepted agent gets adopted and later overwritten | Low | Silent loss of user edits | Adoption runs only after a fleet step exited 0, which requires every target to be generated or receipt-accepted; drift fails the step and prevents adoption |
| Profile rollback adopts unverified files | Low | Same as above | `rollbackInstallProfile` does not pass `agentFleetVerified` |
| A path containing ` #` is truncated | Low | Scope mismatch | YAML itself treats ` #` as a comment; quote the path to keep it |

## P1 Map

`allowed_paths` is read in five places: `scripts/verify-sprint.sh` (`contract_allowed_paths`, awk),
`scripts/contract-run.ts` (`parseList`), `src/core/state/artifact-parsers.ts` (`parseAllowedPaths`,
used by Effective State and the mutation guard), and the duplicated `parseContractAllowedPaths` in
`verify-producer.ts` and `post-bash-importer.ts`. Fleet ownership lives in
`~/.repo-harness/install-state.json#ownership_manifest`, written only by `applyInstallProfile`
(bootstrap with a transaction, update candidate without one); the fleet helper
`scripts/install-agent-fleet.sh` consults it in `compareAndWrite`.

## P2 Trace

#453: each reader stripped `- ` and quotes but kept the rest of the line, so
`AGENTS.md  # note` became the literal pattern. #457: `transactionOwnedSurfaces` records only paths
that did not exist before the transaction, or were already owned; the update candidate calls
`applyInstallProfile` without any transaction. Fleet files installed before ownership tracking, or
during an update, therefore never entered the manifest, and the first fleet projection change
(0.19.4's Codex model family) reported them as drift.

## P3 Decision

Apply YAML's own comment rule in every reader rather than rejecting comments, because the contracts
are valid YAML. Record fleet ownership in the existing manifest at the one moment the fleet helper has
proven each file's provenance, excluding receipt-accepted user-managed agents, instead of teaching
the helper about previous package outputs. The Bun global `package.json` preflight from #457 is a
separate boundary and goes to `tasks/todos.md`.
