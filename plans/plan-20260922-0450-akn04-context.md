## Frozen AKN-04c design

Implement the approved roadmap §8.2 current Task context GET as an independently usable read route. The whole roadmap is approved for implementation and staged PRs; current-task context, historical activity, repository automation observation and UI remain distinct verification boundaries. Source base f5142838 preserves the completed activity source without claiming its pending acceptance.

P1: Strict registry owns repository IDs/read permissions; Board owns canonical schema2 row identity/current revision and Lease projection; collectRepoTaskOffers owns exact Source Ref plan/contract proof, Campaign admission and preparation blocker/owner classification. Server owns Host/Origin/method guards, worker deadlines and cancellation. Browser transport owns request/response identity. No second classifier or document parser.

P2: GET repository/task ID -> strict registry -> selected repository Board -> one exact TaskOffer -> allowlisted canonical row/Claim/proof -> reobserve registry/Board/offer -> strict context DTO -> browser decode. Source Ref is produced by the existing proof resolver, never accepted as input. No arbitrary path, Git ref, title or Plan cell selector. A task with no Lease or unapproved/missing plan remains readable; unknown task/current revision mismatch fails explicitly. Historical task/message recovery remains activity's boundary.

P3: A stable observation is not write authorization. Existing POST remains responsible for lock-time registry/Claim/Lease checks, and no write guard changes here. Publish original blocker code/owner and recorded Claim identity; do not label claimed work running. The response contains proof refs/digests, not raw plan/contract bodies, WorkEnvelope, local worktree/session paths or provider credentials. GET never calls acquire/controller/notify/ACK/provider. Context is observational across Board and proof stores, fail stale on changed observations. At10x scale the existing Board/plan scans dominate; a worker timeout refuses unavailable context rather than falling back to cached authority. No new persistent cache/watch/index/event store.

Request: GET /api/v1/fleet/tasks/:repository_id/:task_id/context with optional task_revision lowercase64hex expected revision. Reject every other/duplicate query key. Response protocol1/kind operator_task_context: repository_id/task_id/task_revision; canonical target ref/OID/sprint relative path; task title/mode/acceptance/task_state; execution lease_state and nullable allowlisted Claim id/generation/state/branch/target_ref; offer execution_readiness/original blockers/offer_revision/nullable exact plan proof explicitly labeled basis registered_worktree; observation time, Board revision, registry authorization revision and consistency observed. Optional expected revision must match, otherwise stale. Browser-safe strict decoder checks closed shapes, bounded strings, relative source paths, enum vocabularies and exact request identity; max serialized response256KiB. Typed failures unavailable/task_not_found/stale/too_large/busy/timeout. Read-only registrations are permitted, bad global registry refused, an unreadable unrelated repository is not collected.

Reuse collectRepoTaskOffers with an optional internal task_id filter before per-card plan work, preserving full Board authority. Capture its actual Board through the existing board_reader seam; do not recompute rows or readiness. Read twice and reject changes in Board revision, selected offer, registry authorization or root. Fields are mapped explicitly. A missing plan stays null with the original blockers. No raw diagnostic error strings cross HTTP.

Server lifecycle: context gets a bounded native Worker path with AbortSignal and existing max_concurrency/deadline configuration. Hold admission until native exit, including after timeout/disconnect; injected readers hold it until settlement; close awaits actual worker exit. Reuse the established activity lifecycle in a private server helper only if it eliminates the two concrete implementations; do not change TaskDiff or collaboration behavior in this slice. Browser adds fetchTaskContext with no-store, AbortSignal and strict identity decode. UI rendering, repository scoped collection/automation summaries and auto-refresh are subsequent roadmap work, not required for this GET to function.

More than8 paths including tests: src/core/operator/task-context.ts, src/effects/operator/task-context.ts, src/effects/operator/task-context-worker.ts, src/operator-web/task-context.ts (new independent wire/effect/worker/transport boundaries); src/effects/fleet/acquire.ts (exact-task selection only), src/effects/operator/server.ts; tests/effects/operator-task-context.test.ts (new current context authority oracle), existing tests/cli/operator-serve.test.ts, tests/unit/operator-web-types.test.ts, tests/effects/operator-write-boundary.test.ts, tests/unit/fleet-acquire-effect.test.ts; docs/researches/20260922-operator-task-context.md and deterministic architecture manifest plus own workflow artifacts. No new dependency/service/configuration/credential.

Verification: current identity/expected revision, no Lease, missing/unapproved/exact Source Ref plan, original blocker owners, false Plan cell, malformed registry, healthy A/unreadable B, private path redaction, changed canonical/proof rejection, unchanged store bytes, HTTP real worker and guards/cancel/admission, strict browser transport, existing activity behavior and targeted offers suite.
