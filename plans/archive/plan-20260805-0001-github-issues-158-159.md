## P1: Architecture map

## P2: Concrete traces

For #158, repo-harness run verify-sprint dispatches the bundled helper; emit_verify_evidence resolves from helper_dir, currently misses the package-owned scripts/ entry, and returns cannot-bind before the ledger/materializer side effect. For #159, a PreToolUse edit supplies all target paths to resolveEffectiveState; fresh failed checks add checks_failed, workflowProfileOrNull suppresses the otherwise valid profile because any blocker is present, and WorkflowProfileGuard exits before ContractScopeGuard can approve the repair path.

## P3: Decision rationale

Resolve #158 by adding the deterministic package-relative scripts/ location before the existing explicit source-root override; this preserves one emitter source of truth and works in the published layout. Resolve #159 at the guard boundary by treating checks_failed as non-authority evidence only for a repo-scoped path that the active contract allows; every other blocker and every out-of-scope target stays fail-closed. The rejected alternative is globally removing checks_failed from hard blockers, because that would also weaken stop/ship semantics and external-path safety. At 10x scale the first pressure point is repeated per-path contract parsing in apply_patch batches, but this slice preserves the existing bounded guard architecture rather than adding a cache abstraction for an unobserved bottleneck.
