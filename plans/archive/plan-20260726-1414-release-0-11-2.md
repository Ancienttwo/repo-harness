## Approach
### Strategy
Prepare only release metadata and workflow evidence in the linked worktree,
merge through GitHub CI, then publish from the exact merged `main` SHA. npm
publication precedes the immutable tag and GitHub Release surfaces.

### Trade-offs
| Option | Pros | Cons | Decision |
|--------|------|------|----------|
| Publish directly from current `main` | Fewer local steps | No reviewed version projection or hosted candidate gate | Reject |
| Release `0.12.0` | Larger semantic boundary | The range contains fixes only and no public breaking contract | Reject |
| Release `0.11.2` through one prep PR | Reviewable version projection, exact-SHA CI and rollback before publish | Requires a small metadata PR | Use |

## Captured Planning Output

## Goal
Publish repo-harness 0.11.2 as one patch release containing only the two fixes already merged after v0.11.1, with npm, Git tag, and GitHub Release bound to the same source commit.

## Success Criteria
- package.json, assets/skill-version.json, .claude/.skill-version, all localized README release projections, docs/CHANGELOG.md, and a dated release filing agree on 0.11.2.
- The release-prep PR is merged with GitHub CI green and exact merged main passes bun run check:release.
- npm latest resolves to repo-harness@0.11.2 with registry integrity and tarball readback.
- Annotated tag v0.11.2 and GitHub Release repo-harness 0.11.2 point to the exact published source commit.
- scripts/check-release-published.sh 0.11.2 and a clean-room installed CLI version readback pass.

## Scope
Version projections, changelog entry for f29a61cc and 76708be1, one release filing, and generated workflow execution artifacts needed to verify and close the release.

## Non-Scope
No product/runtime behavior changes, dependency upgrades, context diet, current.md policy change, writer ownership system, or telemetry semantic change. GitHub Release follows the established no-asset convention; npm is the package artifact authority.

## Due Diligence
P1: package.json is npm version authority; assets/skill-version.json plus .claude/.skill-version and localized READMEs are checked projections. scripts/check-npm-release.sh owns unpublished-version plus CI readiness, scripts/check-release-published.sh owns registry/dist-tag/tarball/tag agreement, and GitHub Actions owns hosted platform verification.

P2: exact main at 76708be1 is projected to 0.11.2 in a contract worktree, verified, merged, verified again at the merge SHA, then published to npm before any tag or GitHub Release is created. Post-publish readback crosses registry metadata, packed tarball, local tag, remote tag, GitHub Release, and clean-room CLI execution.

P3: a patch bump preserves the public contract because both included changes are fixes. npm publication is immutable, so rollback before publish is revert; after publish it is a new patch. If npm auth or publish fails, stop before creating the tag or GitHub Release. At 10x release cadence, manual localized version projections fail first; the existing version checker remains the drift gate rather than introducing a new release abstraction here.
