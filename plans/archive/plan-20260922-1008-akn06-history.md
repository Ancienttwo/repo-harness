## Goal and scope
Implement AKN-06d's bounded historical Task source reader as the independently verified backend prerequisite for old URL recovery. A request contains only registered repository ID, persisted schema2 Task ID and optional expected Task revision. Return the nearest matching first-parent canonical commit, exact Sprint path/blob digest and original Task row; absent, ambiguous or incomplete authority fails closed. This package exposes a typed core/effect API only; existing context HTTP/browser integration is the next checklist work-package, not claimed complete here.

## P1 / P2 / P3
P1: Current operator task-context resolves only active Sprint offers. Historical activity survives Task disappearance but owns messages, not canonical task definition. coordination-identity owns schema2 identity and revision; coordination-canonical-source owns Sprint policy directory and fixed-commit reads. No existing archive resolver provides a complete Task/commit/path tuple. Old title or archive filenames cannot establish identity.
P2: Resolve strict registry and canonical target server-side, pin target commit, traverse its first-parent history newest first (max64 commits), enumerate committed Sprint carriers under each commit's policy directory, parse canonical schema2 rows by the existing identity owner, reject duplicate matching IDs within one commit, and return the first exact ID/revision match. Read the complete carrier set before selecting to prevent ambiguity being hidden by order. Recheck registry physical root/authorization and canonical target commit before return. No live Lease or execution authority is projected.
P3: Git commits are immutable historical evidence, not present readiness. A first-parent traversal deliberately promises only canonical branch snapshots, not every side-branch attempt. Enforce max256 unique Git blobs including policy,2MiB cumulative decoded Git bytes,256KiB per blob,128 carriers per commit,64 commits and3s total deadline; Git commands have remaining-deadline timeout, no lazy fetch/prompts/fsmonitor. Missing schema2 proof is history_unavailable; ambiguity, limits and read failures are named refusals. Reuse the existing policy-directory resolver with a bounded file-read callback so there is one policy parser. No new index/store, API route, environment variable, provider or dependency. At10x history size the fixed budget refuses rather than returning an unproven match.
