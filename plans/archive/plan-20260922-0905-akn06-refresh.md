## Captured Planning Output

## Goal
Implement AKN-06a's browser observation cadence from roadmap section8.3: completion+30s, hidden pause, visible immediate request, bounded failure backoff and exact cancellation. Reuse all existing source readers and one shared lifecycle hook. No new browser write or backend watcher.

## P1/P2/P3
P1: App owns Fleet state and a manual one-queued-request refresh; its fetch currently has no AbortSignal. Collaboration, AutomationSummary and TaskEvidence each own independent request effects with AbortController guards. Organization stays mounted across views. TaskDiff is explicitly loaded and its subject invalidation is a separate AKN-06 review/history slice. Server collectors and provider slots are independent infrastructure under read-only research; this package does not claim their acceptance.
P2: browser source scope -> lifecycle request -> existing strict reader/decoder -> owner state -> completion -> next timeout. Manual refresh and post-send refresh retain one queued Fleet request and refresh selected source generations. Automatic polling keeps current Decision/activity query pages; it does not reset drafts or bind a newer Task/Claim fence into them. A hidden transition cancels the timer and aborts the active read. Visible requests resume immediately, waiting only for an already-aborted uncooperative promise to settle to preserve same-loop single-flight. Scoped cleanup aborts and invalidates old results; rendering keeps existing identity/historical guards.
P3: one hook is justified by four existing consumers sharing timer/cancellation/supersession rules. It owns no domain values, authorization, service epochs or new product state. Each source schedules independently after its own completion, preserving source freshness and avoiding a slow source becoming a global barrier. Healthy cadence is30000ms; consecutive failures wait60000 then120000ms, capped there; success resets. These fixed constants create no config/env surface. At10x load, each mounted observer still has at most one active promise and one queued request; existing bounded server reads are the capacity authority. No new service, credential or provider traffic is required. Abort guards remain effective for readers ignoring cancellation; hidden/unmount cannot start new reads.

## Design
Add src/operator-web/useObservationRefresh.ts with a shared React lifecycle hook accepting a stable async reader, scope/generation identity and initial-read/enabled lifecycle options; return a manual request callback. It holds only timer, current AbortController, one queued request and bounded failure count. Treat the source reader's validated boolean success as scheduling input; errors are displayed by the owning source and never synthesized into successful data.

App delegates only its Fleet request lifecycle to the hook, passes AbortSignal through fetchOperatorSnapshot, retains the existing strict transport decoder and typed test injection, and keeps existing selection/revision checks and manual selected-source refresh generation. Collaboration uses the same hook under repository+Decision cursor+manual generation. AutomationSummary preserves exact service epoch/generation regression checks and historical display. TaskEvidence's existing shared useObservation uses the hook for its two current read consumers. TaskDiff stays explicit and unchanged in this package.

UI navigation, repository selection and stored Composer drafts remain under their existing owners. No countdown, preference, new button, route, schema version or automatic mutation is added. Initial test/SSR snapshots remain accepted initial observations; production starts its existing first read when visible. A supplied static initialCollaboration remains fixture-only data without a reader lifecycle.
