# Prepare the repo-harness 0.19.0 release

## P1 Map

The release surface is metadata and documentation only. Product implementation
for this range is already accepted on `main` at `fd675687`.

- Version authorities: `package.json#version`, `assets/skill-version.json#version`
  and `#templateVersion` (the stamp format is
  `repo-harness@{version}+template@{templateVersion}`).
- Release history: `docs/CHANGELOG.md`.
- Release filing: `deploy/release-checklists/YYMMDD-repo-harness-<version>.md`.
- Human entrypoint docs: `README.md` plus `README.zh-CN.md`, `README.ja.md`,
  `README.fr.md`, `README.es.md`.

## P2 Trace

`v0.18.0..fd675687` is 464 commits and about 210k inserted lines. The
`docs/CHANGELOG.md` `[Unreleased]` section only carries two entries, so the
changelog is the drifted authority and has to be rebuilt for the whole range.

The public CLI surface gained five command groups since `v0.18.0`
(`src/cli/index.ts`): `automation`, `refactor`, `campaign`, `collaboration`,
`external-source`, plus `claude-review`. The README documents none of them.
Host readiness also moved from tmux to herdr, which the README already covers.

## P3 Decision

Release `0.19.0`, not `1.0.0`. Under 0.x cadence a minor may carry breaking
behavior, and the repo's own history takes minors for new public surfaces
(0.17.1 -> 0.18.0 for a protocol bump). A `1.0.0` would be a compatibility
promise this range does not make: the campaign, refactor, and collaboration
surfaces are explicitly gated, and multi-seat collaboration is an accepted
negative decision.

Scope of this work-package: version bump, changelog, README alignment across
five locales, and the release filing. No commit, tag, npm publish, or global
runtime mutation.
