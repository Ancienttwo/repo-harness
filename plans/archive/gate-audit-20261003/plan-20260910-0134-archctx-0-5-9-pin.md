## Captured Planning Output

## P1 Map

The archctx projection provider is pinned in five authority surfaces:

- `package.json` dependencies `archctx` / `archctx-contracts` (exact) and the derived `bun.lock`.
- `src/core/architecture/projection.ts` `ARCHCTX_REQUIRED_VERSION` — the default `requiredVersion`
  when `policy.architecture.projection_version` is absent, and the default argument of
  `assertArchctxCapabilities`.
- `src/core/refactor/policy.ts` `REFACTOR_PROVIDER_VERSION` — the exact stage `provider_version`
  the refactor policy reader accepts and the refactor provider hands to
  `runPackageLocalArchctxJson`, so it resolves the same package-local archctx install.
- `.ai/harness/policy.json` (`architecture.projection_version`, `refactor.stages.*.provider_version`)
  and its generator `assets/templates/helpers/ensure-task-workflow.sh`.
- Test fixtures and `scripts/axr*` clean-room drivers that assert the pinned version literal.

`assets/workflow-contract.v1.json` and `.ai/harness/workflow-contract.json` carry no archctx
version, so they need no change.

## P2 Trace

`assertArchctxCapabilities` (`src/core/architecture/projection.ts`) validates the provider's
`capabilities --json` answer: schema version, exact package name/version, protocol versions,
docs renderer, and `ARCHCTX_REQUIRED_FEATURES` set inclusion. A provider that answers without a
required feature throws `archctx required feature set mismatch`, which fails the handshake closed
before any projection request is sent.

`projection-prior-committed-applies-v1` is the upstream capabilities flag for
`result.priorCommittedApplies`, the field `projectionDeclaredWrites` reads to declare a late write
committed by a killed attempt. Under 0.5.8 the field is absent and the receipt declares nothing,
so a provider that silently drops it is indistinguishable from a provider that never had it. Adding
the flag to `ARCHCTX_REQUIRED_FEATURES` gives that difference a version signal.

## P3 Decision

archctx 0.5.9 and archctx-contracts 0.5.9 are published and carry the feature, so the revisit
trigger recorded in `tasks/todos.md` is met. Move every archctx pin to 0.5.9 in one slice and add
the required feature in the same slice: requiring the feature without moving the pin would fail
every projection closed, and moving the pin without requiring the feature would leave the
undeclared-late-write gap open.

`REFACTOR_PROVIDER_VERSION` moves with the pin because it resolves the same package-local install;
leaving it at 0.5.8 would fail-close every refactor stage against a package that no longer exists
at that version. No sticky/fence/ignore set, timeout, gate, or other behavior changes.
