## Agentic Routing

- Selected route: bugfix
- Routing reason: A completed real workflow proved that direct CLI review bypasses the configured circuit and that bold Markdown findings parse as an empty PASS.
- Due diligence:
  - P1 map: policy and prompt hooks own declared review limits; `src/cli/commands/cross-review.ts` directly invokes the provider runner; `src/core/review/cross-review.ts` parses its transcript.
  - P2 trace: `repo-harness cross-review` captures a subject, invokes Claude, parses only plain `[P1]` lines, and returns without recording any work-package attempt. A semantic edit creates a new subject and the caller can invoke the command again indefinitely.
  - P3 decision rationale: Preserve one semantic review per active contract authority, independent of subject changes. Keep provider retry (`MAX_ATTEMPTS`) separate. Store only an operational, contract-bound invocation receipt and fail closed on a second invocation; do not add a reset or compatibility fallback.

## Approach

### Strategy

Add red tests proving direct CLI review can run exactly once for an active work-package even when implementation content later changes, and proving `**[P1]**` is parsed as blocking. Then connect the direct command to a contract-bound operational receipt without changing provider retry semantics.

### Trade-offs

| Option | Decision | Reason |
|--------|----------|--------|
| Reuse progress-token circuit state | Reject | Real edits change the progress token and would reset the limit, recreating the loop. |
| Bind the review attempt to the active contract/goal authority | Use | A work-package remains the same acceptance unit across finding corrections. |
| Permit a manual reset/re-review flag | Reject | The requested invariant is one review; an escape hatch would reopen the loop. |
| Accept common Markdown wrappers around `[P1]`/`[P2]` | Use | Provider output commonly bolds headings; structured severity must not silently disappear. |

## Promotion Gate

- **Merge/PR unit**: Cross-review admission plus parser regression guards.
- **Rollback surface**: Remove the operational receipt check and restore the old parser together.
- **Verification boundary**: Direct invocation tests, parser tests, typecheck, workflow gates.
- **Review/acceptance boundary**: One semantic review only; findings are corrected and then owner acceptance closes the package without recursive external review.
- **High-risk surface**: Acceptance routing and false-PASS prevention.
- **Why not checklist row**: This changes shared acceptance behavior and needs an isolated rollback boundary.
