## Design Decisions

- Use patch version `0.11.2`: `v0.11.1..main` contains two fixes and no public
  API, configuration, dependency, or compatibility-boundary change.
- Publish npm before creating `v0.11.2` or the GitHub Release. This keeps the
  recoverable boundary before npm's immutable version transaction.
- Keep GitHub Release assets empty, matching `v0.11.1`; the npm registry tarball
  remains the package artifact authority.
- Keep the release worktree metadata-only. The product fixes are already merged
  and verified independently as `f29a61cc` and `76708be1`.
- The default global npm auth returns `E401`. Use the established ignored
  `_ops/env/npm.md` token only through a temporary npmrc and temporary cache;
  never print the token or mutate global npm configuration.
- Keep `bun run check:release` outside the contract verifier's parallel
  `commands_succeed` list. The first verifier attempt ran the full release gate,
  typecheck, and focused tests concurrently; `check:type` and `check:release`
  failed under that shared-worktree race even though their isolated component
  checks passed. The release gate is an explicit serialized freeze check.

## Tradeoffs Considered

| Option | Decision | Reason |
|--------|----------|--------|
| Publish directly from current `main` | Reject | It would bypass reviewed version projections and hosted candidate CI. |
| Cut `0.12.0` | Reject | No breaking or additive public contract requires a minor line. |
| Cut `0.11.2` through one release-prep PR | Use | Smallest reviewable unit with rollback before publish and exact-SHA readback. |
