## Design Decisions

- Release as `0.15.0`, not `0.14.3`, because `v0.14.2..main` contains a `feat`
  commit and the `/check` ship rule maps a backward-compatible feature to minor.
- Treat `package.json.version` and both `assets/skill-version.json` fields as
  the enforced authority set. The READMEs and AXR7 constant are projections;
  `.claude/.skill-version` is an older repository stamp and the Oracle `0.14.2`
  test value is a third-party fixture, not a release authority.
- Stop this work-package before npm publish, tag creation, GitHub Release, or
  global install mutation. Those irreversible/external actions require a later
  explicit authorization and exact-main CI evidence.

## Deviations From Plan Or Spec

- The first full release gate found one unrelated flaky assertion in
  `tests/unit/closeout-runner-guardrails.test.ts` (2363 pass, 1 skip, 1 fail).
  The focused test immediately passed. Inspection proved the assertion raced
  contender lock acquisition against producer exit, even though production
  releases the token after provider-group drain and then calls `process.exit`.
  Scope was widened for this single release-blocking test repair; production
  code remains unchanged.
- The corrected invariant passed 10 consecutive focused runs and the complete
  `closeout-runner-guardrails` file passed 24/24.

## Tradeoffs Considered

| Option | Decision | Reason |
|--------|----------|--------|
| Patch `0.14.3` | Reject | The release range contains a backward-compatible feature. |
| Minor `0.15.0` | Use | Matches the repository ship rule and public capability change. |
| Prepare and publish in one slice | Reject | It crosses the reversible candidate boundary before user review. |
