## Design Decisions

- The release contract was right-sized by diffing the fresh capture against the
  archived `0.15.3` contract (`tasks/archive/contract-20260819-2050-release-0-15-3.md`)
  before running the first gate, per the 2026-08-19 release-ritual lesson. Three
  accommodations were carried over rather than re-derived: `Task Profile: docs-only`,
  `commands_succeed` limited to the three sandbox-safe commands (`check:type`,
  `check-deploy-sql-order.sh`, `check-task-sync.sh`), and both Change Assessment
  oracles (`release-deterministic-gates` deterministic_test,
  `published-package-runtime-readback` runtime_readback, both `paths: ["*"]`)
  declared from candidate prep instead of after a gate verdict. The structural
  diff between the two contracts is now limited to identifiers, dates, the
  version-specific prose, and the rewritten `commands_succeed` comment.
- The architecture drift cursor was anchored by running
  `bash scripts/check-architecture-sync.sh` on the clean tree immediately after
  `bun install`, before touching any version anchor. That run returned
  `changed_capabilities=0 blocking=0`; the post-edit run returned
  `changed_capabilities=3 blocking=0`. Without this the fresh worktree has no
  cursor, and the first projection run against an already-dirty tree processes
  the entire working tree as one delta and dead-letters as
  `unresolved-major-change` — the failure mode that cost 0.15.3 a recovery round.
- The release filing's own bytes necessarily post-date the gates it records.
  Everything else in the candidate was final when `check:release` and the
  standalone `bun test` ran, and the filing adds no code, no packaged file, and
  no gate input. This is stated explicitly in the filing rather than left
  implicit.
- Skill eval was not run. `bun run benchmark:skills` drives live `claude` and
  `codex` agent runs against `evals/evals.json`, which is outside candidate-prep
  boundaries; per `docs/reference-configs/release-deploy.md` the absence is
  recorded as unavailable rather than substituted, matching 0.15.3.

## Tradeoffs Considered

| Option | Decision | Reason |
|--------|----------|--------|
| `0.15.4` patch vs `0.16.0` minor | `0.16.0` | The 0.15.3 filing reserved `0.16.0` in writing for the release where WP2 and WP3 ship together; both landed in this range, and the surface grows by a new CLI verb plus two hook behaviors |
| Include `check:release` / `check-architecture-sync.sh` in `commands_succeed` | Exclude | The bounded verifier's `scrubHarnessEnv()` strips `REPO_HARNESS_NODE_BIN` while archctx needs Node >=24 <26 and the protected PATH carries only v22.22.0; both run outside the sandbox with results recorded in the filing |
| Write the filing before vs after the gates | After, with the ordering disclosed | A filing that records its own gate results cannot be inside the gated content; disclosing the ordering is honest, backdating it is not |
