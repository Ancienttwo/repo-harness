## Why

`v0.14.2..main` contains one backward-compatible hook capability plus its
authority cutover and a cursor-retention bug fix. Publishing without a coherent
minor-version candidate would either misclassify the public change or allow the
npm version, downstream workflow stamp, documentation, packed hook bundle, and
consumer proof to drift.

## Goal

Prepare, verify, merge, and push the exact `repo-harness@0.15.0` candidate while
leaving npm publication, `v0.15.0`, the GitHub Release, and the selected global
installation untouched for a later explicit release action.

## Scope

- In scope: release version authorities/projections, five README current-release
  lines, AXR7 packed-version assertion, changelog, release filing, packed hook
  bundle, the directly blocking leaderless-provider cleanup test assertion, and
  workflow-owned projections needed to close this contract.
- Out of scope: product behavior changes, dependency changes, compatibility
  paths, historical release files, the unrelated Oracle fixture string, npm
  publish, tag/GitHub Release creation, and global installation mutation.
- Taste constraints: keep the release diff mechanical and auditable; each
  changelog claim must map to a commit in `v0.14.2..candidate`.

## Stop Conditions

- Stop and hand back to the parent if the change would require editing a path outside Allowed Paths.
- Stop if an Exit Criteria command cannot be run in this environment.
- Stop if Goal, Scope, or Exit Criteria are internally contradictory.

## Falsifier

If the current version checker or packed tarball readback proves another live
version authority, the enumerated surface is incomplete and the contract must
be widened before editing it. Cheapest proof: run `check-skill-version`, inspect
all live `0.14.2` matches, and compare the 0.14.2 release diff shape before the
candidate gate.

## Root Cause Evidence

Required when Task Profile is `bugfix`; leave as-is otherwise.

- root_cause: one sentence naming file:line/condition (testable, not "a state issue").
- repro: the command or UI path that reproduces the symptom.
- regression_guard: path to a test that fails on the unfixed code and passes after the fix (must also appear under exit_criteria.tests_pass).
- pre_fix_failure_artifact: path to a captured run of regression_guard on the UNFIXED code. Capture with `bun test <regression_guard> > <artifact> 2>&1; echo "PRE_FIX_EXIT=$?" >> <artifact>` (no pipes — pipes swallow the exit status). The gate requires a non-zero `PRE_FIX_EXIT=` line plus the regression_guard path string in the artifact (see the Root Cause Evidence Gate section in docs/reference-configs/sprint-contracts.md).
