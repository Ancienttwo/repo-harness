## Why

The version anchors, the changelog, and the release filing are the local audit
trail for an immutable npm release. If they disagree with the published
artifact, the installed runtime, the tag, and the registry stop resolving to
one release, and the next release inherits an unrecoverable ambiguity about
what `0.16.0` actually contained. `0.16.0` additionally carries a promise made
in writing by the 0.15.3 filing — that this minor marks the kanban coordination
program landing complete — so a filing that misstates the range breaks a claim
consumers were told to expect.

## Goal

Produce a `repo-harness@0.16.0` release candidate on `codex/release-0-16-0`
whose version anchors, changelog section, and release filing all agree, with
every repository release gate run at the candidate's final content and its real
result recorded in the filing. Publication is explicitly not part of this
outcome.

## Root Cause Evidence

Required when Task Profile is `bugfix`; leave as-is otherwise.

- root_cause: one sentence naming file:line/condition (testable, not "a state issue").
- repro: the command or UI path that reproduces the symptom.
- regression_guard: path to a test that fails on the unfixed code and passes after the fix (must also appear under exit_criteria.tests_pass).
