## Design Decisions

- Use patch version `0.11.3`: `v0.11.2..main` is exactly one squash commit
  (`80460452`, PR #135) adding ChatGPT delegate mode plus two same-day
  follow-up fixes (mandatory egress Gitleaks scan, host skill projection).
  None of the three changes alter a public API, config schema, or dependency
  contract, so a minor line is not warranted.
- Kept the release-prep worktree metadata-only, mirroring the 0.11.2
  precedent: `package.json`, `.claude/.skill-version`,
  `assets/skill-version.json`, the five localized README projections,
  `docs/CHANGELOG.md`, and the dated release filing.
- Ran every T4 gate against the repo-local source (`bun src/cli/index.ts run
  check-task-workflow --strict`, `bash scripts/*.sh`) instead of the globally
  installed `repo-harness` CLI. Confirmed the global binary resolves to
  `0.11.2` (`repo-harness --version`) while this worktree is mid-bump to
  `0.11.3` — running gates through the stale global CLI would check the
  wrong version authority. This is the same class of drift the
  `tests/todos.md` helper-scripts flake note warns about for
  `REPO_HARNESS_SOURCE_ROOT`/`repo-harness run verify-sprint`.
- Followed the 0.11.2 notes lesson: kept `bun run check:release` (the full
  local release gate) outside the contract's parallel `exit_criteria.
  commands_succeed` list, and kept `tests_pass` narrow to
  `tests/skill-version.test.ts` and `tests/bootstrap-files.test.ts` rather
  than a full-suite entry. `commands_succeed` also excludes evidence-producer
  commands (`adopt --dry-run`, `inspect-project-state`) per the same
  precedent — those already run inside `check:release`'s own `check-ci.sh`
  step and would be redundant/racy as a second parallel invocation.
- Did not run the contract acceptance ceremony (`verify-sprint
  --prepare-acceptance` / `repo-harness run verify-contract --strict`) or
  mark the contract/review as Fulfilled/Passed. This dispatch's scope was
  version projection, changelog, release filing, and the named T4 gates;
  recording an AcceptanceReceipt is a ship/acceptance judgment left to the
  next stage.
