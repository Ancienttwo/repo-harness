## Release gate resolved, acceptance rejected on Windows durability (2026-09-10)

Release-gate execution vx-29d11f7e074c48acb914 remains a failed run and stays
recorded above. Its single failure is now diagnosed: macOS `timed` performed an
NTP SYNC at 2026-09-10 20:49:09.454 local that stepped the wall clock backwards
between the `publishAutomationBudget` and `reserveAutomationBudgetAdmission`
samples, producing the 21 ms `automation_budget_clock_regression`. The unified
log carries the step; the code's sampling order was verified correct and was not
changed. The focused rerun of `tests/effects/campaign-authoring-resume.test.ts`
passed 26/26. Forced rerun vx-09c0b0b29f8e49cdb6fa passed (exit 0, 44 minutes)
with the force reason recorded. Branch CI run 34479638051 was green.

Codex acceptance review then REJECTED the candidate on a Windows durability
finding: `syncCheckpointPath` fsynced checkpoint files and directories through
`O_RDONLY` handles, which `FlushFileBuffers` rejects on win32 (EPERM for a
read-only handle, unsupported for a directory handle), so checkpoint publication
threw and the Stop handler swallowed it -- a silent regression against 0.18.0,
which had no durability barrier. Fixed in this commit: the platform decision is a
pure `checkpointSyncPlan(platform)` (win32 opens files `O_RDWR` and performs no
directory fsync; POSIX keeps `O_RDONLY | O_NOFOLLOW` plus directory fsync), both
branches are asserted from any host, and `tests/evidence-checkpoint.test.ts` now
runs in the Windows CI matrix job.

npm publication and installed-runtime readback remain pending.
