## CI Repairs

- `tests/effects/operator-automation-summary.test.ts`: main's scoped snapshot
  test expected repository snapshot protocol 2; the epoch slice (5057b27b)
  deliberately bumped it to 3.
- `tests/effects/operator-task-context.test.ts`: the Planning graph fixture used
  `plans/policy:module.json`, a filename Windows cannot create, so the
  canonical graph was unavailable on the Windows matrix. The fixture now uses
  `plans/policy-module.json`.
- `tests/unit/me1b-engineering-overlay.test.ts` (authority change): ME-1B's
  first slice forbade any `effects/operator/` importer of the Engineering
  Overlay. The overlay PRD
  (`plans/prds/20260824-1653-engineering-overlay-control-board.prd.md`) forbids
  overlay-owned web routes and UI mutation endpoints in that slice, and the AKN
  roadmap (`docs/researches/20260921-agent-first-kanban-implementation-roadmap.md`
  §7, §10) routes the Organization view through the existing read-only
  collaboration GET. The guard now allows exactly
  `effects/operator/collaboration.ts` and `core/operator/organization-snapshot.ts`
  (type-only imports), keeps `operator-web/` forbidden, and checks
  `OPERATOR_ROUTES` for no Engineer/overlay/organization route with the
  collaboration snapshot still a GET, non-write route.
- Task history on Windows: the 64-commit budget test returned `timeout` because
  the reader spawned two `git ls-tree` processes per walked commit (policy file
  and Sprint directory; 130 Git processes for 64 commits, measured with
  `GIT_TRACE`). The reader now resolves `<commit>:<path>` for all walked commits
  in one `git cat-file --batch-check='%(objecttype) %(objectname)'` process;
  a blob's mode comes from a non-recursive listing of its parent tree, and each
  distinct tree is listed once. The same test uses 4 Git processes. The
  format deliberately avoids `%(objectmode)`, which needs Git 2.51; a test
  pins the format to atoms that older Git supports. The history tests pass
  under both Apple Git 2.50.1 and Git 2.51.0. Returned records, symlink and
  gitlink refusal, the 3000 ms deadline and every refusal code are unchanged.
  Identical tree listings are read once, so they count once against the byte
  budget.
