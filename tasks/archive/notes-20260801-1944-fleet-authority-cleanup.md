# Notes: fleet authority cleanup

Plan: `plans/plan-20260801-1625-fleet-authority-cleanup.md`

## Decisions and deviations

- **`.claude/agents/` deleted but `.codex/agents/` kept**: these two directories
  look like a symmetric pair of "this repo's own agent config", and the original
  dispatch treated them that way, but they are not the same kind of artifact.
  `.claude/agents/*.md` is a plain tracked duplicate of `agents/fleet/*.md` — no
  test reads it (`tests/install-agent-fleet.test.ts` compares the installed
  Claude `.md` against `FLEET_SOURCE_DIR`, which is `agents/fleet`), and the
  duplicate had already drifted: `.claude/agents/fast-worker.md` still declared
  `model: sonnet` / `effort: max` against the authored `opus` / `medium`, and its
  boundaries bullet was missing the "or the gate's" clause. `.codex/agents/*.toml`
  is the installer golden: `tests/install-agent-fleet.test.ts:10` binds
  `GOLDEN_CODEX_DIR` to it and line 135 asserts `expect(installedCodex).toBe(golden)`,
  `tests/bootstrap-files.test.ts:88` asserts each of the seven exists, `.gitignore`
  carves it out of the blanket `.codex/*` ignore, and
  `docs/architecture/modules/workflow-engine/contract-assets.md:222-223` names it a
  golden. Deleting it would have forced either dropping byte-identity (a real test
  relaxation — it is what catches TOML escaping, field ordering, and heredoc
  boundary regressions that the `toContain` assertions cannot) or relocating golden
  authority, which is an architecture decision, not an execution one. Escalated and
  the A path (keep and regenerate) was chosen.

- **Golden regenerated through the installer, not hand-edited**: because
  `gatekeeper`'s frontmatter changed, `.codex/agents/gatekeeper.toml` had to move
  with it. Hand-editing the golden would defeat its purpose — the golden's value is
  that it is a captured installer output, so hand-writing the expected bytes would
  make the byte-identity assertion tautological. Regenerated by running
  `scripts/install-agent-fleet.sh` into a throwaway `HOME` and copying the produced
  file over the golden, which is the same path `prepareInstallerRuntime()` uses in
  the test. The other six goldens were confirmed byte-unchanged by the same run.

- **`gatekeeper` Codex projection is an explicit override, not a family default**:
  after the respec to `model: opus` / `effort: high`, the `opus` family default
  would have projected gatekeeper to `gpt-5.6-terra` at `high`. It is instead
  pinned in `AGENT_TARGET_OVERRIDES` to `gpt-5.6-terra` at `xhigh`, matching the
  existing `deep-worker` precedent of bumping Terra one effort tier above the
  authored Claude-side tier. This keeps the acceptance gate reasoning at the same
  depth it had under the retired `fable`/`xhigh` spec; a plain family default would
  have quietly demoted it.

- **HOME targets and fixtures deliberately untouched**: a repo-wide sweep for
  `.claude/agents` / `.codex/agents` returned matches in `.ai/harness/policy.json`,
  `scripts/lib/project-init-lib.sh`, and the `ensure-task-workflow.sh` pair — all
  `~/`-prefixed HOME install targets, which are the product surface governing
  downstream generation and must not move when this repo drops its own tracked
  copy. `tests/install-profiles.test.ts`, `tests/create-project-dirs.runtime.test.ts`,
  and `tests/subagent-handler.test.ts` matches are all fake-HOME or tmp-repo
  fixtures. None of these were changed.

## Open questions

- The `.claude/agents/` deletion means in-repo agent spawn now resolves to the
  user-level install written by `install-agent-fleet.sh`. That is the intended
  single-authority outcome, but it does mean a developer who has never run the
  installer gets no fleet in this repo. No fallback was added — that would be
  exactly the compatibility path the root contract forbids.
