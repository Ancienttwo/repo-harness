# repo-harness-product

Bot entrypoint. Confirm the product goal and source requirements.

## Mode Selection

- A real new product needs a PRD: `references/prd.md`.
- A requested backlog needs ordering: `references/sprint.md`.
- A requested bounded Goal session needs preparation: `references/goal.md`.

## Task Authority

The GitHub issue and PR own task identity, claim, status and dependencies.
Before preparing execution, read the current issue, assignees, all comments and
linked PRs. Follow the repository's issue-claim rules. Planning references do
not authorize work or override an active claim. Do not mint task IDs,
contracts, offers or leases.

## Boundaries

Use a short worker brief or PR description for ordinary tasks.
Do not mark artifacts Approved on the user's behalf. Preserve existing approval.
Deferred work stays in GitHub issues. Product planning does not install
ChatGPT or execute backlog work. Delegate execution only within the existing
authorization and named scope.
