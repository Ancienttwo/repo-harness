# BRC default-model session admission

> Historical record. Campaign execution moved to the existing Bot skills on 2026-10-04. Use [repo-harness](../../SKILL.md) to dispatch and collect work through Herdr/OAR. Use [repo-harness-product](../../assets/skills/repo-harness-product/SKILL.md) for planning and [repo-harness-check](../../assets/skill-commands/repo-harness-check/SKILL.md) for scope and verification. repo-harness has no campaign runtime.

Campaign session ownership no longer depends on backend model identity. The user-selected ChatGPT model/thinking values remain untouched and `BrowserSessionMeta.model.verified` remains observationally false. No new provider run is performed by this implementation.

The shared campaign browser-session evidence producer requires a completed Oracle result and matching local metadata, exact repository and Chrome profile root/directory, the invocation-owned descriptor's provider session, and actual selected GitHub composer-pill evidence. Initial sessions require no parent; a continuation must name the stored source session's provider identity. Two equal but foreign parent fields are insufficient. Continuation requires source evidence and an unchanged repository/profile binding before reserving budget; adoption checks the same binding before challenge I/O. Invalid source evidence cannot start another unprovable child call.

Authoring sessions and Connector challenges/receipts use protocol 2. Old model-only session records and boolean-only challenge inputs fail closed; there is no migration or dual read. Authoring embeds structured evidence and derives its verification field from that evidence. Challenge inputs bind the source provider identity, and receipts retain the response provider identity and evidence digest. Recovery validates the same terminal/session/profile/parent evidence before accepting the saved response. Model identity, session ownership, content matching and exact revision remain separate facts.

The first regression failed on the original implementation: a completed default-model session with descriptor and GitHub evidence was persisted as unverified solely because model.verified was false. Focused tests cover that case, absent or misbound evidence, wrong profile/root/provider, foreign parent, legacy protocol rejection, tampering, response recovery and existing campaign heartbeat behavior. A failed post-repair drift fixture was aligned to provide valid session lineage so it reaches the unchanged source-drift gate; unverified-edit and missing-evidence refusals remain independently covered.

No dependencies, service or public CLI surface were added. One core evidence module serves authoring and adoption; one shared test fixture supplies the same realistic browser metadata to their tests. The protocol cutover deliberately makes historical stopped canary records ineligible for new admission. Those records remain original research evidence and are neither rewritten nor resumed.

BRC6a remains Owner-closed. BRC15a's negative observation and the exact metadata/budget mapping are in `20260908-brc15a-offline-metadata-replay.md`. This package does not create a trusted revision receipt, remove `requireCampaignActiveAdmission`, accept a fresh audit or start active/manual Canary 3. Final verification and independent acceptance are owned by the work-package contract and its receipt.
